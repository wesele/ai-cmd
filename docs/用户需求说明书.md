## 1. 产品定位

AI Command 是一款面向开发者和系统管理员的命令行辅助工具，通过人工智能技术，让用户用自然语言描述想做什么，工具自动生成对应的 shell 命令并执行。

**一句话描述：** 说人话，就能执行命令。

---

## 2. 用户角色与场景

### 2.1 用户角色

| 角色 | 特征 | 核心需求 |
|------|------|---------|
| **开发人员** | 熟悉编程，经常使用命令行 | 快速执行复杂命令，减少查文档时间 |
| **运维人员** | 需要管理系统，执行各类运维操作 | 安全执行命令，避免误操作系统 |
| **普通用户** | 不熟悉命令行 | 用简单语言完成文件管理、系统查询等操作 |

### 2.2 使用场景

#### 场景1：快速查找文件
**用户：** 开发人员小李  
**需求：** 想在当前目录查找所有大于100MB的文件  
**传统方式：** 需要记住 `find` 或 `Get-ChildItem` 的复杂参数  
**使用 ai-cmd：** 输入 `ai 查找当前目录大于100MB的文件`，工具自动生成并执行命令

#### 场景2：系统进程管理
**用户：** 运维人员老张  
**需求：** 找出占用8080端口的进程并结束它  
**传统方式：** 先查端口占用，再查进程ID，再结束进程，多步操作  
**使用 ai-cmd：** 输入 `ai 杀掉占用8080端口的进程`，一步完成

#### 场景3：危险操作预警
**用户：** 运维人员老张  
**需求：** 清理日志文件，但不确定命令是否安全  
**使用 ai-cmd：** 工具用红色高亮显示 `rm -rf` 等危险命令，等待确认，避免误操作

#### 场景4：跨平台工作
**用户：** 开发人员小李  
**需求：** 在公司用 Windows，在家用 Linux，总记混命令  
**使用 ai-cmd：** 工具自动识别系统，生成对应平台的命令（PowerShell 或 Bash）

## 3. 用户需求列表

### 3.1 核心需求：自然语言转命令

**需求编号：** UC-001  
**需求名称：** 自然语言转换为shell命令  
**优先级：** 高  
**用户故事：** 作为一名用户，我希望用自然语言描述我想做什么，这样我就不需要记住复杂的命令语法。

**验收标准：**
- 输入："列出当前目录所有文件"
- 输出：对应的 shell 命令（如 `ls -la` 或 `Get-ChildItem`）
- 支持中英文混合输入
- 响应时间在3秒以内

**示例：**
| 用户输入 | 期望输出（Windows） | 期望输出（Linux） |
|---------|-------------------|------------------|
| 列出当前目录所有文件 | `Get-ChildItem` | `ls -la` |
| 查找所有.log文件 | `Get-ChildItem -Filter *.log -Recurse` | `find . -name "*.log"` |
| 显示系统IP地址 | `Get-NetIPAddress \| Where-Object {...}` | `ip addr show` |

---

### 3.2 核心需求：命令安全提示

**需求编号：** UC-002  
**需求名称：** 命令危险等级提示  
**优先级：** 高  
**用户故事：** 作为一名用户，我希望在执行命令前看到危险等级提示，这样我可以避免误执行危险操作。

**验收标准：**
- 命令生成后，用不同颜色显示危险等级
- 绿色：只读操作（安全）
- 黄色：创建内容（低风险）
- 橙色：修改/删除单个对象（中风险）
- 红色：批量删除/系统级操作（高风险）
- 高风险命令需要明确确认才能执行

**示例：**
```
> rm -rf /tmp/*
显示为：[红色文字] rm -rf /tmp/*
```

### 3.3 核心需求：多平台支持

**需求编号：** UC-003  
**需求名称：** 跨平台自动适配  
**优先级：** 高  
**用户故事：** 作为一名跨平台工作者，我希望工具能自动识别我的操作系统并生成对应命令，这样我就不用记两套命令了。

**验收标准：**
- 在 Windows 上自动生成 PowerShell 命令
- 在 Linux 上自动生成 Bash 命令
- 同一句自然语言，在不同平台生成对应的正确命令

### 3.4 配置需求：快速配置

**需求编号：** UC-004  
**需求名称：** 交互式配置向导  
**优先级：** 中  
**用户故事：** 作为一名普通用户，我希望通过简单的问答方式配置API信息，而不需要手动编辑配置文件。

**验收标准：**
- 运行 `ai -c` 启动配置向导
- 向导引导我选择AI平台（OpenAI、百度等）
- 提示我输入API Key（输入时不显示明文）
- 百度平台需要额外输入Secret Key
- 提供默认端点地址和模型名称，我可以直接按回车使用默认值
- 配置完成后提示保存成功并显示配置文件位置

**配置流程：**
```
1. 选择AI平台：OpenAI / 百度文心一言
2. 输入API Key：********
3. （若选百度）输入Secret Key：********
4. 输入API端点：[默认地址，可直接回车]
5. 输入模型名称：[默认模型，可直接回车]
6. 配置完成，保存到 ~/.ai-cmd.json
```

### 3.5 配置需求：多渠道配置

**需求编号：** UC-005  
**需求名称：** 支持多种配置方式  
**优先级：** 中  
**用户故事：** 作为一名开发人员，我希望可以通过环境变量、配置文件等多种方式配置工具，这样我可以根据场景选择最方便的方式。

**验收标准：**

### 3.6 调试需求：问题排查

**需求编号：** UC-006  
**需求名称：** 调试模式  
**优先级：** 低  
**用户故事：** 作为一名开发人员，我希望在工具出问题时能看到详细的运行日志，这样我可以快速定位问题。

**验收标准：**
- 使用 `ai -d "命令"` 启用调试模式
- 调试信息输出到终端（不影响正常命令输出）
- 显示API调用信息、命令生成过程、执行结果
- 默认不启用，避免干扰正常使用

**调试信息示例：**
```
[INFO] 输入: "列出文件"
[INFO] 调用API: OpenAI, 模型: gpt-4o-mini
[INFO] 生成命令: ls -la, 危险等级: green
[INFO] 命令执行成功
```

### 3.7 执行需求：确认机制

**需求编号：** UC-007  
**需求名称：** 命令执行前确认  
**优先级：** 高  
**用户故事：** 作为一名用户，我希望在命令执行前有机会检查命令内容，这样我可以在发现不对时取消执行。

**验收标准：**
- 生成命令后，显示命令内容
- 提示"按Enter执行，Ctrl+C取消"
- 如果不确认，可以按Ctrl+C退出，不会执行命令
- 只有按Enter才执行命令

**交互流程：**
```
> ai 删除temp目录所有文件
> rm -rf /tmp/*
(Press Enter to execute or Ctrl+C to cancel)
[用户按Enter] → 执行命令
[用户按Ctrl+C] → 不执行，退出
```

## 4. 使用流程

### 4.1 首次使用流程

```
1. 安装 ai 工具
2. 运行 ai -c 启动配置向导
3. 选择AI平台（OpenAI / 百度）
4. 输入API Key
5. 配置完成
6. 开始使用：ai <自然语言>
```

### 4.2 日常使用流程

```
用户输入：ai 想做的事情
         ↓
工具显示加载动画
         ↓
工具显示生成的命令（带颜色标识危险等级）
         ↓
用户按Enter执行 或 Ctrl+C取消
         ↓
显示命令执行结果
```

### 4.3 调试使用流程

```
用户输入：ai -d 想做的事情
         ↓
（调试信息输出到终端）

         ↓
工具显示生成的命令
         ↓
用户确认执行
         ↓
（调试信息显示执行结果和退出码）
```

## 7. 附录：用户常见问题

### Q1：支持哪些语言输入？
A：支持任意自然语言输入，工具会将你的输入发送给AI模型处理。中英文混合也没问题。

### Q2：生成的命令一定正确吗？
A：不一定。AI生成的命令仅供参考，执行前请务必仔细检查，特别是红色危险命令。

### Q3：我的API Key安全吗？
A：API Key保存在本地配置文件中（~/.ai-cmd.json），请确保文件权限设置正确。调试模式不会输出API Key。

### Q4：可以离线使用吗？
A：不可以。工具需要调用AI API进行命令转换。

### Q5：为什么有些命令生成不准确？
A：AI模型的理解能力有限，建议用更清晰、具体的语言描述你的需求。也可以尝试换一个模型。

### Q6：如何切换到其他大模型？
A：可以通过 `ai -c` 配置向导，或修改 `~/.ai-cmd.json` 配置文件，更改 `endpoint` 和 `model` 字段。支持任何兼容 OpenAI API 的服务。
